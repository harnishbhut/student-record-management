About Student Record Management System

The Student Record Management System is an academic web application designed to provide college faculty and department administrators with a reliable, streamlined tool for tracking student admissions, academic progress, and enrollment information.

Project Purpose & Objective

In many collegiate departments, tracking student information using paper ledgers or fragmented spreadsheets leads to duplicate entries, data loss, and security risks. This system provides a unified, centralized platform that performs complete CRUD (Create, Read, Update, Delete) operations with validation and SQL injection protection.

Technology Stack

  • Backend: Python 3 with the lightweight Flask web framework.
  • Database: SQLite3 with parameterized SQL queries for persistent relational storage.
  • Frontend: Semantic HTML5, structured CSS3 with a traditional academic design, and vanilla JavaScript.
  • API Layer: RESTful JSON API supporting standard HTTP methods (GET, POST, PUT, DELETE) and status codes (200, 201, 400, 404, 409).
  • Testing: Automated test suite utilizing Python's built-in unittest module with isolated test databases.
  • Version Control: Git for clean tracking of commits and repository changes.

REST API Endpoints

External client applications and services can interact with the system via the following REST API endpoints:

GET /api/students - Retrieve all students (supports ?search= and ?course=)
GET /api/students/<id> - Retrieve a single student by ID
POST /api/students - Register a new student (JSON body)
PUT /api/students/<id> - Update an existing student record (JSON body)
DELETE /api/students/<id> - Delete a student record by ID

Software Engineering Principles Demonstrated

  • Separation of Concerns: Database access logic is isolated in database.py, route controllers in app.py, and UI presentation in templates and stylesheets.
  • Data Integrity & Validation: Both client-side JavaScript and robust server-side Python validators protect against empty values, bad email formats, and duplicate records.
  • Security: All SQL queries use parameterized bindings (? placeholders) to completely prevent SQL injection attacks.
  • User Experience: Helpful error messages, confirmation dialogs for destructive actions, and responsive feedback.
